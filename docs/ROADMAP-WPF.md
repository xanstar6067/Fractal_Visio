## 0. Принципы переноса

1. **Палец, а не мышь.** Цели не меньше 48 dp (`UiTheme.SegmentHeight`). Колесо → щипок,
   правая кнопка → долгое нажатие, Ctrl/Shift-модификаторы → отдельные жесты или кнопки, поля ввода
   чисел → слайдеры (логарифмические, где диапазон широкий) и лесенки вариантов. Клавиатура —
   только для имён и формул. Наведения (hover) нет: всё, что в WPF было подсказкой, должно быть
   видно или не нужно.
2. **Одна панель — одна тема.** В WPF у окна фрактала слева колонка на всё сразу. На телефоне это
   экран прокрутки, в котором ничего не найти. Здесь — нижняя панель инструментов с подписями и
   панели по темам: фрактал, цвет, закладки, снимок, настройки.
3. **Плавный рендер общий для всех режимов.** Прогрессивные проходы, композиция кадров
   (`FramePlacement` / `FrameCompositor`), широкий слой, инерция, удерживаемый кадр, бюджет
   потоков и времени — всё это уже есть и не дублируется. Новый escape-time фрактал — это семплер,
   определение и шейдер. Режим с другой моделью (накопление точек, векторная графика, 3D) —
   это новый *тип движка* рядом с нынешним, а не особый случай внутри него.
4. **Правила `CLAUDE.md` действуют и здесь**: слои asmdef, состояние только в `FractalSession`,
   строки только через локали, размеры только в dp, сохранения в инвариантной культуре.
5. **Порядок — от дешёвого и заметного к дорогому.** Сначала то, что закрывает дыру в
   пользовательском опыте или стоит «три файла»; потом движки, которые открывают целые разделы
   каталога.

### Блок 2. Семейство Мандельброта: дешёвые варианты — 🔶 начат (2026-09-23), риск н

Каждый вариант — рецепт из `ARCHITECTURE.md` §6: семплер fp64 + семплер пертурбации + шейдер +
определение + строка каталога + строки локали. Ни рендерер, ни UI не меняются.

- ✅ Tricorn, Celtic, Multibrot (p = 3…8, параметр «Степень») — в галерее, GPU и CPU, глубокий
  зум пертурбацией. Сверка с double-double на сетках вокруг граничных точек (1e-13, 1e-17, 1e-21):
  Tricorn и Multibrot — ни одного расхождения; Celtic — ни одного на обычных границах, а в
  областях хаотических ограниченных орбит результат решает шум округления в любой арифметике
  (там и fp64 расходится с double-double уже на 1e-4).
- ⏭ Buffalo из WPF не переносится: в WPF это `(|x| + i|y|)² + c` — зеркальная копия их (и теперь
  нашего, см. ниже) Burning Ship, то есть тот же фрактал вверх ногами.
- ⏳ Simonobrot и дробная степень.
- Попутно исправлено: шейдеры Burning Ship и размытия стекла не были в Always Included Shaders — в
  сборке на телефон `Shader.Find` их не находил (Burning Ship только на CPU, стекло без размытия,
  у карточки нет превью). Теперь в списке все шейдеры, а шаг внесён в рецепт.

| Вариант | Итерация | Пертурбация |
|---|---|---|
| Tricorn (Mandelbar) | `z = conj(z)² + c` | `d' = conj(2Zd + d²) + dc`, rebasing по модулю |
| Buffalo | `z = (|x| + i|y|)² + c` | свёртка по компонентам, rebasing покомпонентный (как Burning Ship) |
| Celtic | `x' = |x² − y²| + cx`, `y' = 2xy + cy` | свёртка только вещественной части результата |
| Multibrot (целая p = 3…8) | `z = zᵖ + c` | биномиальное разложение `(Z+d)ᵖ − Zᵖ`; параметр `power` (Int) |
| Simonobrot, дробная p | как в WPF | только fp64 (как и в WPF, упирается в точность) |

Готово, когда: каждый вариант открывается из галереи, совпадает с WPF на тех же координатах,
глубокий зум до ~1e-20 без артефактов (сверка с `*SamplerDD`, как в §4.8).

✅ Попутно (2026-09-24, вместе с блоком 3): Burning Ship был перевёрнут относительно WPF. WPF
считает `zi = −|zi|` (корабль стоит мачтами вверх), Unity считал `+|zi|`. Знак сменён в семплерах и
шейдере, сохранения получили версию 2: вид корабля из старого файла отражается по `y` при чтении
(`StateCodec.Upgrade`), так что закладки показывают то же место. Buffalo из WPF теперь — ровно
прежний корабль Unity, то есть зеркальная копия нового; поэтому он по-прежнему не переносится.

### Блок 3. Жюлиа и выбор C пальцем — ✅ сделан (2026-09-24), кроме 3.5; риск с

Пересмотрено 2026-09-24 по отзыву: долгое нажатие на Мандельброте как вход в Жюлиа — связь
неочевидная. Вместо жеста — **отдельная кнопка «Карта C»**, которая показывает саму карту.
Подробности устройства — `ARCHITECTURE.md` §5.8 и §4.8.

- 3.1 ✅ `JuliaDefinition`, `JuliaBurningShipDefinition`: старт `z₀ = пиксель`, `c = параметр`.
  Комплексный параметр — два `Double` (`c_re`, `c_im`) плюс контракт `IParameterPlane` в Core:
  «эта пара — точка на плоскости такого-то фрактала», с рамкой карты и известными точками.
  Пертурбация: опорная орбита из центра вида, rebasing — на **критическую орбиту** (орбиту нуля),
  а не на `Z₀`: для Мандельброта это одно и то же, для Жюлиа только так `d = z` остаётся точным
  около критической точки, и внутренность сходится вместе с опорой (BLA пропускает её).
  Сверка с double-double на 1e-13 / 1e-17 / 1e-21 (кролик Дуади, базилика, диск Зигеля) — ни
  одного расхождения, в 3–10 раз быстрее DD; у Жюлиа корабля 0–2% пикселей в областях, где исход
  решает округление (fp64 расходится с DD там уже на 1e-6).
  У Жюлиа корабля C по умолчанию — «Психонавт» из пресетов WPF: умолчание WPF (игла) даёт линию
  поперёк экрана, никудышную как первый кадр и карточка галереи; оно осталось пресетом.
- 3.2 ✅ Burning Ship разворачивается как в WPF (`zi = −|zi|`, мачты вверх) до появления Жюлиа
  корабля — иначе известные C из WPF пришлось бы зеркалить. Сохранения версии 1 с видом Burning
  Ship отражаются по `y` при чтении (`StateCodec`, версия 2).
- 3.3 ✅ **Кнопка «Карта C»** справа сверху, напротив кнопки галереи: живая миниатюра
  Мандельброта (для корабля — корабля) с точкой текущей C и подписью. Тап открывает панель
  «Константа C»: крупная карта, палец ставит и ведёт C, два пальца (колесо) — масштаб и сдвиг
  карты, «+» / «−» и «Весь план». Пока карта открыта, картинка сдвигается в свободную часть
  экрана, чтобы Жюлиа была видна целиком; C меняется под пальцем вживую, пока рисует GPU, и при
  отпускании — на глубине, где считает CPU.
- 3.4 ✅ В панели «Фрактал» у Жюлиа: C числом, «Выбрать на карте» и известные C из WPF (кролик
  Дуади, дендрит, …). У Мандельброта и корабля — кнопка «Жюлиа для центра экрана»: обратная связь
  тоже через кнопку, а не жест.
- 3.5 ⏳ Галерея C (WPF `JuliaGalleryWindow`): лист с сеткой превью вокруг текущей C, тап выбирает.
- 3.6 ⏳ Проверка на устройстве: щипок и ведение по карте настоящими пальцами (в редакторе касания
  имитировались вызовами `PlaneMapInput`), скорость живого обновления C на GPU телефона.
- 3.7 ✅ Исправлено после первой сборки (2026-09-24): на телефоне у обоих Жюлиа не было превью в

- 4.2 **Превью закладок.** `IAppStorage` учится хранить байты. При сохранении закладки, когда

- 4.3 **«Сохранённые» в галерее**: чип рядом с «Недавними», карточки с превью, тап открывает

- 4.4 **Экспорт в высоком разрешении.** Сейчас «Снимок» растягивает кадр экрана до выбранного

  «Отмена» в тосте. «Как на экране» без сглаживания остаётся мгновенным копированием кадра.
  Размер, сглаживание и формат — в «Настройках», рядом с размером снимка. На Android после
  сохранения тост предлагает «Поделиться» (снимок уже в MediaStore, его адрес и отдаётся).
  Задуманный `IFrameCapture` из `ARCHITECTURE.md` §5.2 стал сервисом `IFrameExport` (§5.9).
- 4.5 ⏭ Импорт сохранений WPF (`MandelbrotState` JSON) — по желанию, если нужен перенос коллекции.

### Блок 5. Раскраска уровня WPF — риск в (формат буфера)

- Режимы: Histogram, Orbit Trap, Stripe Average, Smooth Escape Polynomial, Distance Estimation
  с освещением «рельеф» и контурами.
- Буфер escape-значений становится многоканальным (escape + данные режима), GPU-шейдеры считают
  то же самое. Инвариант «одна формула позиции в палитре на CPU и GPU» распространяется на каждый
  режим.
- Палитры: гамма, повтор / зажим / зеркало, полосы или градиент, цвет интерьера, встроенные
  палитры WPF. В UI — сетка палитр с полосками цвета вместо списка имён.
- Перекраска остаётся перекраской: режимы, которым хватает данных буфера, переключаются без рендера.

### Блок 6. Глубина за пределом decimal — риск в

- Центр вида в произвольной точности (порт `BigFloat` / `BigMantissa`), масштаб и отклонения в
  `FloatExp` за 1e-300. Сохранения уже пишут координаты строками — формат не ломается.
- Опорная орбита в `BigFloat`, когда `DoubleDouble` не хватает (глубже ~1e-30).
- Адаптивный бюджет итераций по предыдущему кадру + ручной множитель «Детализация».
- `RealBlaTable` для Burning Ship и свёрнутых вариантов блока 2.
- «Навести на минимандельброт» (метод Ньютона, WPF `MandelbrotNewtonZoom`) — кнопка в панели
  «Фрактал» с анимированным перелётом.
- Засев CPU-буфера содержимым GPU на переключении бэкенда (`ARCHITECTURE.md` §8).

### Блок 7. Другие escape-time семейства — риск с

- Newton Pools+ (Newton / Halley / Householder): сначала фиксированные многочлены с GPU-шейдерами,
  затем парсер выражений (порт `CompiledComplexExpression`) и байткод-интерпретатор в шейдере.
- Nova (Мандельброт / Жюлиа), Phoenix (+ пад параметров C1/C2 по образцу блока 3), Коллатц,
  экспонента Ляпунова (последовательность A/B — ряд чипов вместо поля ввода).
- Глубокий зум для них — после блока 6.

### Блок 8. Бассейны притяжения (11 режимов WPF) — риск с

Общий движок по образцу `BasinExplorerEngine`. На сенсоре естественнее, чем мышью: центры
маятника и притягивающие центры перетаскиваются пальцем, долгое нажатие показывает орбиту точки.

### Блок 9. Накопительные визуализации — риск в (новый тип движка)

Buddhabrot / Anti-Buddhabrot, IFS (Барнсли, Хейуэй), Fractal Flame, Серпинский (игра хаоса),
странные аттракторы (Clifford, de Jong, Tinkerbell, Gumowski–Mira), Хенон, Икэда.

- Новый движок: разбрызгивание точек в гистограмму плотности (compute shader, CPU-запасной путь),
  тональная кривая, палитра. Картинка улучшается со временем; смена вида перезапускает накопление,
  а композитор по-прежнему размещает кадр одного вида.
- Редакторы аффинных преобразований на сенсоре — перетаскиваемые треугольники вместо таблиц чисел.

### Блок 10. Геометрические и рисуемые — риск с

L-системы (пресеты чипами, правила — клавиатура), Аполлонова прокладка, DLA (живая симуляция),
обратное дерево Коллатца. Векторный движок: линии и окружности в меш, перетесселяция при зуме.

### Блок 11. Динамические системы — риск с

Лоренц и Рёсслер (3D-кривая, вращение одним пальцем), орбиты логистического отображения и
диаграмма бифуркации (графики с осями), Gray–Scott — реакция-диффузия на GPU, реагент рисуется
пальцем (лучший кандидат на «вау» для сенсора).

### Блок 12. 3D-фракталы — риск в

Мандельбульб, Жюлиабульб, Мандельбокс, губка Менгера, тетраэдр Серпинского, кватернионное Жюлиа,
аполлонова упаковка сфер, объёмные IFS. Ray marching во фрагментном шейдере; сенсорная камера:
один палец — трекбол вокруг схваченной точки поверхности, щипок — к точке под пальцами, два пальца
— сдвиг, поворот двух пальцев — крен, двойной тап — посмотреть на точку. Принцип плавности тот же:
грубый кадр в движении, досчёт в покое.

### Блок 13. Математические лаборатории (18) — риск н по отдельности, много работы в сумме

Первыми — те, что лучше всего ложатся на палец: эпициклы Фурье (контур рисуется пальцем), фигуры
Хладни и Domain Coloring (GPU), филлотаксис, гиперболические мозаики, Вороной / Ллойд
(перетаскивание центров), инверсия окружностей / Мёбиус. Остальные — по одной.

### Блок 14. Производительность и платформа — риск с

Burst + Jobs для CPU-проходов (этап 9 в `ARCHITECTURE.md`), прогрев шейдеров, Android: скрытие
системных панелей, «Поделиться», вибро-отклик на долгое нажатие; планшеты — проверка трёх колонок
панели и сетки галереи.

### Блок 15. Сервис — риск н

«О программе» (версия, папка данных), журнал ошибок, «что нового». Облачная синхронизация — вне
плана, пока не понадобится.

## 4. Проект меню

### 4.1 Два места

1. **Галерея — главное меню.** Открывается при запуске. Полноэкранный лист матового стекла поверх
   живого фрактала.
   - Шапка: «Фракталы» и кнопка настроек.
   - Чипы фильтра (горизонтальная прокрутка): Все · Избранное · Недавние · разделы каталога.
   - Карточка «Продолжить» (только в «Все»): текущий кадр, имя фрактала, глубина. Тап — вернуться
     туда, где остановились.
   - Карточки фракталов, сгруппированные по разделам: живое превью в текущей палитре, имя, строка
     описания, звезда избранного в углу превью (своя цель 48 dp). Открытый сейчас фрактал обведён.
   - Число колонок — от ширины: минимум 150 dp на карточку, 2 колонки на телефоне в портрете,
     4–6 на планшете.
2. **Исследование — фрактал на весь экран.**
   - Слева сверху: кнопка «▦ Имя фрактала» — назад в галерею.
   - Справа сверху, только у Жюлиа: кнопка «Карта C» — живая миниатюра Мандельброта (корабля) с
     точкой C; открывает панель с большой картой (блок 3).
   - Панель инструментов: снизу в портрете, справа в ландшафте. Пять кнопок с иконкой и подписью:
     **Фрактал** (параметры, сброс вида, описание) · **Цвет** (палитра, раскраска, редактор) ·
     **Закладки** · **Снимок** · **Настройки**. Кнопка открытой панели подсвечена.
   - Панели выезжают у панели инструментов: листом снизу в портрете, колонкой справа в ландшафте.
     Одна панель за раз.

### 4.2 Жесты и кнопки

| Действие | Жест |
|---|---|
| Сдвиг | один палец |
| Масштаб и поворот | два пальца |
| Сброс вида | три пальца, или «Сбросить вид» в панели «Фрактал» |
| Закрыть панель | тап по картинке вне панели, или кнопка панели ещё раз |
| Спрятать / показать интерфейс | тап по картинке, когда панелей нет |
| Назад (Android) | панель → интерфейс → галерея; в галерее двойное нажатие — выход |

### 4.3 Раскладка

```
Телефон, портрет                   Телефон, ландшафт
┌────────────────────┐             ┌──────────────────────────────────┐
│ [▦ Мандельброт]    │             │ [▦ Мандельброт]            ┌────┐│
│                    │             │                  ┌───────┐ │ ⚟  ││
│      фрактал       │             │     фрактал      │ панель│ │ ◐  ││
│ ┌────────────────┐ │             │                  │       │ │ ★  ││
│ │ панель (лист)  │ │             │                  └───────┘ │ ◉  ││
│ └────────────────┘ │             │                            │ ⚙  ││
│ [⚟  ◐  ★  ◉  ⚙]   │             │                            └────┘│
└────────────────────┘             └──────────────────────────────────┘
```

Всё в dp и внутри `Screen.safeArea`. Панель инструментов не длиннее доступной стороны экрана:
при большом масштабе интерфейса кнопки ужимаются, а не уезжают за край.

## 5. Открытые вопросы

- **Режимы, которые не escape-time** (блоки 8–13). Нужен второй контракт рядом с
  `IFractalDefinition` — что-то вроде `IExplorationMode` со своим движком и своим презентером. Галерея
  уже работает с `CatalogEntry`, поэтому в каталог такой режим встанет без правки галереи;
  решение принимается в начале блока 9.
- **Превью для глубоких закладок.** GPU рисует только до `GpuMinimumScale`; превью закладки
  поэтому снимается с экрана в момент сохранения (блок 4), а не рендерится заново.
- ~~**Комплексный параметр.**~~ Решено в блоке 3: два обычных `Double` плюс контракт
  `IParameterPlane` («эта пара — точка на плоскости такого-то фрактала»). Отдельный вид параметра
  не понадобился. Phoenix (блок 7) с двумя C потребует от контракта нескольких плоскостей — тогда
  `IParameterPlane` станет списком.
